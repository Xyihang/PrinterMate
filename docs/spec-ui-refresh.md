# 一、需求澄清清单（Clarify）

## 核心诉求

> 界面在**功能不变**的前提下,从"十年期工具软件"改造成 **Windows 11 Fluent 原生风格**,
> 同时解决"文字太多、信息太散、找不到功能"三个可用性问题。

## 目标用户

- 主用户：**本机使用者本人**(个人自用)
- 次用户：拿到 EXE 的普通 Windows 用户(不含任何厂商驱动,需自行获取)
- 共同特征：**非 IT 专业人员**,不熟悉"免驱 / UPD / PCL6 / IPP"等术语

## 使用场景

| 场景 | 频率 | 界面要求 |
|---|---|---|
| 插 USB 线 → 连接 → 打测试页 | **最高频** | 三步之内完成,首屏可见 |
| 换新电脑/新打印机时装驱动 | 低频但关键 | 状态与"下一步该干什么"必须一眼看懂 |
| 排查"为什么打不出来" | 低频 | 诊断信息要能快速定位 |
| 阅读教程 | 首次 | 内容要能扫读,不是大段文字 |

## 用户已确认的痛点（全选）

1. ✅ 视觉观感陈旧（配色 / 字体 / 间距 / 圆角）
2. ✅ 表格 / 列表样式太原始（无斑马纹、无悬停态、无空状态）
3. ✅ 说明文字太多太啰嗦
4. ✅ 信息密度与排版松散（一屏看不到几个关键信息）
5. ✅ 找不到功能 / 导航不直观（纯文字导航、7 项平铺、无图标无分组）

## 用户已确认的边界

| 维度 | 决定 |
|---|---|
| 改造幅度 | **视觉 + 布局重排**（可动页面内部分组与导航结构；**不改交互流程**） |
| 风格方向 | **Windows 11 Fluent 原生风** |
| 深色模式 | **不做** |
| 功能逻辑 | **一点不改**（红线） |
| 单元测试 | **395 个必须继续全部通过**（红线） |

## ⚠️ 需要用户复核的两处偏差（重要）

### 偏差 1：用户未勾选"安全校验与许可确认不得弱化"

用户在红线选项中只勾选了两项,未勾选该项。**本规格仍将其视为不可触碰的红线**,理由:

- "安全校验"属于**功能逻辑**,已被用户勾选的"功能逻辑与行为一点不改"覆盖;
- 弱化许可确认（如把勾选框藏进折叠区、把风险提示删掉）会造成**授权与合规风险**,
  这不是界面取舍,而是法律暴露。

**规格中的处理**:许可勾选框、白名单说明、三重校验说明、风险提示 ——
**位置与排版可以调整,但必须仍然可见、必须仍然需要用户显式操作、语义不得改变。**

### 偏差 2：用户选择"深色模式不做，维持现状"，但该选项描述为"颜色继续写在页面里"

现状是 **46 处硬编码颜色分散在 4 个页面**,这正是"视觉观感陈旧、不统一"的根因之一。
若不把它们集中,就无法达成"统一到 Fluent 风格"这个已确认的目标。

**规格中的处理**:**不实现深色模式**,但颜色**必须集中到资源字典**。
这是达成视觉统一的必要手段,与深色模式无关。

# 二、现状盘点（实测数据，非估计）

|---|---|

| 视图 XAML 总行数 | **749 行** |

# 三、功能规格文档（Define）

## 3.1 目标（Goal）

在不改功能逻辑、不改交互流程、不弱化安全校验的前提下：

1. 建立**设计令牌层**（颜色 / 字号 / 间距 / 圆角 / 阴影），消除全部硬编码；
2. 建立**控件样式层**（统一的按钮 / 输入 / 下拉 / 复选框 / 表格 / 列表 / 滚动条 / Expander）；
3. 改造**导航**（加矢量图标 + 分组）；
4. 改造**信息表达**（长文字收敛为"一行摘要 + 可展开 / ToolTip"，降低纵向长度）；
5. 改造**页面内部结构**（分组重排，让主操作在首屏可见）。

## 3.2 功能清单

| 编号 | 功能模块 | 优先级 | 描述 |
|---|---|---|---|
| F1 | 设计令牌与资源字典 | **P0** | 颜色/字号/间距/圆角/阴影集中定义，全应用引用 |
| F2 | 控件样式统一 | **P0** | 隐式样式覆盖 WPF 默认外观，含各状态（悬停/按下/禁用/焦点） |
| F3 | 导航改造 | **P0** | 矢量图标 + 分为「核心流程」「配置与帮助」两组 |
| F4 | 表格与列表现代化 | **P0** | 表头样式、斑马纹、行悬停、选中态、空状态占位 |
| F5 | 说明文字收敛 | **P0** | 默认一行摘要，详情进可展开区或 ToolTip |
| F6 | 页面内部结构重排 | **P0** | 按"主操作优先"重排分组，压缩纵向长度 |
| F7 | 状态与反馈区统一 | P1 | 顶部的操作/结果/建议三行改为统一的信息条组件 |
| F8 | 空态 / 加载态 / 错误态 | P1 | 三态统一视觉，不再出现空白页 |
| F9 | 窗口尺寸与响应 | P1 | 设定合理的默认尺寸与最小尺寸，避免内容被裁切 |
| F10 | 键鼠可达性 | P1 | 统一的焦点可视化、Tab 顺序合理 |
| F11 | 深色模式 | **不做** | 本次明确不做，但结构上保留切换口 |

## 3.3 详细规格

### F1 设计令牌与资源字典

- **输入**：现有 46 处硬编码颜色 + 各页面内联的字号/边距
- **处理**：归入单一资源字典，按语义命名（如 `Brush.Accent`、`Brush.Surface`、`Brush.TextSecondary`、
  `Brush.Danger`、`Brush.Warning`），而非按外观命名（不出现 `Blue1`）
- **输出**：全应用零硬编码颜色值
- **异常处理**：若某处颜色确实无法归类，必须在规格评审中说明，不得静默硬编码

### F3 导航改造

- **输入**：现有 7 项平铺文字导航
- **处理**：加入矢量 Path 图标；按用途分为两组
  - **核心流程**：新手必读 → 设备发现与连接 → 打印与测试页 → 任务队列与状态
  - **配置与帮助**：驱动管理 → 设置
- **输出**：导航可扫读，图标不引入任何图标库（用矢量 Path 内联）
- **异常处理**：图标缺失时回退为纯文字，不得导致导航项消失

### F5 说明文字收敛（对应痛点"文字太多"）

- **输入**：各页面内联的大段说明文字
- **处理**：
  - 保留一句**摘要**在同位置（默认可见）
  - 其余详情移入 **Expander（默认收起）** 或 **ToolTip**
- **输出**：页面首屏信息量提升，纵向长度下降
- **异常处理**：**风险提示、许可确认说明、安全校验说明不得移入折叠区或 ToolTip**
  （见"需用户复核的偏差 1"）

### F6 页面内部结构重排（对应痛点"信息密度松散"）

- **输入**：现有各页面分组顺序
- **处理**：按"使用者最可能先做的事"排序；次要信息下沉
- **输出**：主流程页面（设备发现）在 1280×800 下**首屏可见主操作**
- **异常处理**：不得删除任何现有分区，只允许调整顺序与显隐方式

## 3.4 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 滚动流畅：**保持既有"每页单一滚动宿主"规则**，内层表格/列表禁用自身滚动条 |
| 兼容性 | 保持 `net8.0-windows`；**不新增任何 NuGet 依赖** |
| 可维护性 | 硬编码颜色 **46 → 0**；新增页面只需引用令牌 |
| 可测试性 | **395 个单元测试必须 100% 通过** |
| 国际化 | 本次不做，但文案不得再硬编码进布局属性 |
| 可访问性 | 文本对比度满足 WCAG AA（正文对比度 ≥ 4.5:1） |

## 3.5 接口规格

- **不新增**任何对外 API
- ViewModel 层**仅允许新增纯展示用属性**（如 `IsEmpty`、`GroupName`、`IconKey`）
- **不得**新增或修改任何业务行为、命令语义、校验逻辑

## 3.6 数据规格

**无数据模型变更。** 不涉及 `drivers.json`、审计日志格式、分发策略存储。

# 五、风险与依赖

## 5.1 技术风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 替换 WPF 默认控件模板 | 影响面覆盖所有页面 | 用**隐式样式**集中在资源字典，问题集中在一处修复 |
| 表格虚拟化与嵌套滚动冲突 | 滚动卡顿复发 | 沿用既有 `EmbeddedGrid`/`EmbeddedList` 规则，不改动该机制 |
| 图标引入方式 | 误增 NuGet 依赖 | 只用内联矢量 `Path`，不引入图标库 |
| 布局重排导致控件被裁切 | 功能"看不见了" | 逐页实际点开验证 + 设定最小窗口尺寸 |
| 文案精简时误删风险提示 | **合规暴露** | 风险提示类文案一律不动语义，仅可调整排版 |

## 5.2 外部依赖

- **无新增依赖**。不引入 MahApps / HandyControl / ModernWpf 等 UI 库。
- 图标全部用内联矢量路径。
